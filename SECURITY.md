# Security policy

## Supported versions

Only the latest release and the current `main` receive fixes. There is no
maintenance branch.

| Version | Supported |
|---|---|
| 1.0.x | yes |
| < 1.0 | no |

## Reporting a vulnerability

Report privately, not through a public issue: open the repository's
[**Security** tab](https://github.com/kodetix-fr/tv-track/security/advisories/new)
and use *Report a vulnerability*. The report stays visible only to you and the
maintainers until a fix is published.

Useful in a report:

- what an attacker gains, and what they need to already have
- the affected file, endpoint or Firestore path
- the steps that demonstrate it, against your own Firebase project

Expect an acknowledgement within a week. This is a small project maintained on
free time: there is no bounty, and fixes ship when they are ready. Please hold
public disclosure until a fix is out, or for 90 days, whichever comes first.

## Scope

The repository itself carries no credentials — Firebase configuration,
keystores, service account keys and API keys are all injected at build time and
gitignored. Reports about a key found in someone's fork or build belong to that
deployment, not here.

In scope, and worth reporting:

- a way to read or write another user's data under `users/{uid}`, whether
  through [`firestore.rules`](firestore.rules) or the client
- a flaw in the Google sign-in flow or in how the session is held
- an API key or token leaking into logs, crash reports or a build artifact
- a dependency vulnerability that is actually reachable from the app

Out of scope: findings that require a rooted or physical-access device, reports
generated by a scanner with no demonstrated impact, and issues in TheTVDB, TMDB
or Firebase themselves — report those to the provider.
